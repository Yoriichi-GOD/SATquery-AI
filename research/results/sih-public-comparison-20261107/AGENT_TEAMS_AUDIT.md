# Public source audit: three SIH / SatQuery repositories

Audit date: 2026-11-07. Public read-only retrieval through the GitHub connector. Repository files below are pinned to the full default-branch commit observed during this audit. This is a source inspection, not an execution or accuracy replication.

## Scope and evidence rules

Inspected the prominent README or submission README, repository metadata and complete recursive file trees, core orchestration/input/model code, selected tests, and published result artifacts. No competitor code was executed; no repository was cloned; no packages, weights, datasets, credentials or hosted demos were installed, downloaded or used. Published percentages are **repository-reported**, unless their derivation is explicitly identified below. A code path or saved JSON does not establish that the current deployed application or checkpoint reproduces it.

The three repositories are public examples in the broader search cohort. They are not verified SIH finalists. No common held-out dataset, common hardware, or head-to-head experiment was run. The comparison therefore supports capability/evidence gaps, not an overall winner.

## 1. divyptl/SIH-2026

### What is actually implemented

Automatic routing is real and explicitly deterministic: input count/modality chooses single, optical–SAR, or bi-temporal; single-image location words choose grounding; the controller checks compatibility, selects a registered specialist, applies a resolution gate, executes the runner, and returns evidence plus trace. This is observable specialist orchestration, not an autonomous LLM planner. Determinism alone is not a defect. [Controller](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/backend/agent/controller.py#L76), [routing and execution](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/backend/agent/controller.py#L194), [query rules](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/backend/agent/controller.py#L466).

The temporal specialist is substantial code: shared Siamese features, multi-scale temporal differences, change-mask head, question/visual cross-attention, answer logits and softmax confidence. Backend runners load the change checkpoint and produce masks/region evidence. A pipeline test constructs a tiny dataset, prepares and loads it, performs a forward/backward training step, and checks tiled inference restores a 600×700 mask. These tests were read, not run. [Temporal model](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/ml/C_VQA/model.py#L520), [backend runner](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/backend/services/specialists.py#L350), [pipeline tests](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/ml/C_VQA/test_pipeline.py#L140).

Optical–SAR implementation is also real: separate SAR/optical embeddings, cosine matching, a learned terrain head with softmax probabilities, plus optical proxy and SAR water estimates. The checkpoint loader sizes the terrain head from the checkpoint so old four-class weights are supported. This demonstrates implemented cross-modal model interfaces; it does not independently validate the masks or terrain accuracy. [Fusion inference](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/ml/fusion/inference.py#L78), [terrain inference](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/ml/fusion/inference.py#L228), [backend fusion output](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/backend/services/specialists.py#L431).

### Strong public evidence and material limits

The README is unusually candid: single-image VQA/captioning has no working specialist/checkpoint, the VQA import is broken after a rewrite, and the general VLM fallback is disabled. That admission conflicts with the checked mandatory VQA box farther down the same README. The inspected baseline implementation confirms a fixed placeholder answer, or specialist-context text, rather than a general VLM call. Some trace/warning text still says that a generic VLM answered. [README models and limitations](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/Readme.md#L77), [placeholder baseline](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/backend/agent/controller.py#L530), [misleading fallback wording](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/backend/agent/controller.py#L283).

Input validation has limits: declared modality wins, otherwise filename/channel heuristics guess the sensor. Pair compatibility rejects differing aspect ratios and warns about resolutions/georeferencing; it does not compare actual CRS/bounds or acquisition dates in the inspected function. Matching dimensions therefore do not establish co-registration. Unknown GSD is allowed with a warning. [Modality inference](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/backend/services/images.py#L77), [pair checks](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/backend/services/images.py#L297), [resolution gate](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/backend/agent/controller.py#L494).

The saved v2 test result reports 4,262 questions: overall VQA 82.5%; 960 Dynamic World questions VQA 81.35%, mask F1 0.5799; 3,302 LEVIR-derived questions VQA 82.83%, mask F1 0.8834. The same artifact reports only 26.52% on 362 “where” questions and 61.67% on 60 water-trend questions. These disaggregations are stronger evidence than a single headline score; generated labels/questions and different resolutions remain different evaluation conditions. [Saved v2 result](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/results/change_vqa_v2_test.json).

Older benchmark tables report 93.78% VQA and 89.42% change F1, while the compact result JSON marks VQA as “training epoch 10” and leaves mask_f1 null. Do not mix these with the newer test result or with another repository's CDVQA score. [Older table](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/results/benchmark_tables.md), [older result provenance](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/results/benchmark_results.json).

The README reports grounding validation/test results and a small eight-chip Sen1Floods11 water-share check, while explicitly admitting that RGB optical “NDWI” is a brightness proxy with large over-counting and that the current fusion head lacks a trained water class. These claims were read, not independently replicated; water fraction is not exposure accuracy. [README measured claims and limits](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/Readme.md#L77).

Confidence here is model score/softmax with coercion and a missing-score default of 0.5, not demonstrated calibrated correctness probability. There are useful explicit narration tests against invented boxes, counts, directions and figures; they do not validate scientific accuracy. [Aggregation](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/backend/agent/controller.py#L345), [narration tests](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/backend/agent/test_narration_grounding.py#L46). Checkpoint download is environment-configured and supports private access; exact public checkpoint identity/version was not established. [Weight fetch code](https://github.com/divyptl/SIH-2026/blob/589f5d59564a2c02911fe825c5577321f57f9ae1/deploy/fetch_weights.py#L20).

**Fair characterization:** a serious implemented temporal/grounding/fusion competitor with valuable tests and candid limitations; incomplete mandatory single-image VQA, limited pair verification, and heterogeneous benchmark provenance.

## 2. cattolatte/satquery

### What is actually implemented

The controller inspects inputs, classifies/reconciles the query, selects tools based on query and availability, invokes them, combines output and confidence, and returns a trace. It can select the generative specialist for VQA/captioning/change, retain a heuristic for selected class-change questions, use detector/patch grounding, and append a grounding pass to cross-modal analysis. Parameter-name filtering is implemented in Tool.invoke. The accepted ADR explicitly chooses deterministic registry selection over an LLM planner. [Controller](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/satquery/controller/agent.py#L39), [selection](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/satquery/controller/agent.py#L96), [parameter filter](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/satquery/tools/base.py#L60), [ADR](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/docs/adr/0001-agentic-controller.md).

Input code reads raster metadata, infers modality from filename/band descriptions/counts, rejects unreadable inputs, more than two images, incompatible modalities, different CRSs and nonoverlapping bounds. Missing georeferencing is an assumption with a trace note; equal acquisition dates are only a warning. Bounds overlap is not pixel-level registration, and sensor inference is still heuristic. [Inspector](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/satquery/io/inspect.py#L24), [pair checks](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/satquery/io/inspect.py#L119).

Remote-sensing adaptation has executable substance: SmolVLM base + optional PEFT adapter loading; a LoRA training loop with backward/optimizer steps, held-out answer sampling, checkpoints and adaptation metadata. The temporal path can feed two ordered images to that generative specialist; a separate heuristic produces patch-divergence change maps and class-area deltas. SAR ingestion handles VV/VH/ratio, already-dB inputs, nonfinite values and optical band packing. This is more than naming model families in a README. Exact adapted weights were not verified. [Generative load](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/satquery/tools/generative.py#L160), [LoRA training](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/satquery/adapt/train_vlm.py#L148), [two-image inference](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/satquery/tools/generative.py#L242), [temporal heuristic](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/satquery/tools/multi_image.py#L48), [sensor preprocessing](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/satquery/tools/specialists.py#L38).

### Strong public evidence and material limits

The README reports 55.2% VRSBench VQA, ROUGE-L 0.306, grounding Acc@0.5 28.0%, 64.3% routed CDVQA and 51.7% RSVQA-LR, with 173 claimed weight-free tests. The repository includes result JSONs and detailed ablations/regressions. This is the strongest close public comparator of these three for broad measured VQA/adaptation coverage. “Strongest” here is a source-evidence assessment, not a replicated accuracy ranking. Tests inspected cover query ambiguity/reconciliation and actual SAR composite properties/synthetic GeoTIFF ingestion; none were run in this audit. [README](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/README.md#L93), [benchmarks](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/docs/BENCHMARKS.md), [routing tests](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/tests/test_router.py), [SAR tests](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/tests/test_sar.py).

The optical–SAR denominator matters: its saved 600-pair artifact reports P@3 optical 0.3450, SAR 0.3617, fused max 0.3756 — **+1.39 percentage points over the better current sensor**. The 18.9% shown beside 37.6% in the README is an older fused result, not the current better-single-sensor reference. The detailed benchmark document correctly exposes the smaller gain. No uncertainty interval was established here. [Saved cross-modal result](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/eval/results/crossmodal.json), [detailed denominator](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/docs/BENCHMARKS.md#L206).

There is a concrete benchmark-to-product parity gap. CrossModalTool only builds a combined ranking when params contains a shared vocabulary. The benchmark calls the tool directly with vocab=LAND_COVER and fusion=max. The normal /api/query handler calls Controller.run(q, saved) without parameters, and the controller forwards an empty dictionary by default. On this inspected web path the benchmark's fused ranking is therefore not automatically activated; side-by-side sensor readings and agreement still are. This narrows the README's broad “every number through the real serving path” wording. [Fusion condition](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/satquery/tools/multi_image.py#L205), [benchmark direct invocation](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/eval/crossmodal.py#L95), [web invocation](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/satquery/server.py#L144), [controller defaults](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/satquery/controller/agent.py#L39).

CDVQA is a 300-question subset, not the entire benchmark; routed overall is 64.33%, with 14.29% smallest-change, 38.10% largest-change and 35.71% change-ratio in the saved artifact. The detailed narrative and controller comments are not perfectly synchronized about largest-change routing; use the pinned code and result, not prose alone. [Saved routed result](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/eval/results/cdvqa_controller.json), [current routing regex](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/satquery/controller/agent.py#L124), [benchmark narrative](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/docs/BENCHMARKS.md#L162).

Confidence is not validated calibration: free generation returns a fixed 0.65 when adapted and 0.3 otherwise; constrained answers use a hand-set margin transformation; cross-modal uses clipped embedding agreement; controller uses the minimum plus fixed penalties. These are transparent heuristics. [Generative confidence](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/satquery/tools/generative.py#L265), [cross-modal confidence](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/satquery/tools/multi_image.py#L272), [aggregation](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/satquery/controller/agent.py#L215).

The roadmap acknowledges counting/comparison regressions and dataset transfer limits, but its open SAR-preprocessing item is stale relative to the inspected implementation. Do not repeat that particular item as a current missing capability. [Roadmap](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/docs/ROADMAP.md), [current SAR code](https://github.com/cattolatte/satquery/blob/c3acd278160dabc4c2f2eca2a113129b53d5bd12/satquery/tools/specialists.py#L56).

**Fair characterization:** substantial query-driven specialist selection, genuine adaptation/temporal/SAR implementations and unusually detailed result reporting; limited sample sizes, heuristic confidence, missing verified weight identity, and a real cross-modal serving/evaluation configuration gap.

## 3. Argho009/sih-2026

### What is actually implemented

The public API serves a single patch at a time. The manager unconditionally runs a DL classifier, RF classifier and GIS path, fuses class probabilities with normalized user weights, then optionally calls LM Studio through a fixed LLM alignment → VLM visual reasoning → LLM synthesis sequence. It falls back to direct VLM/LLM or keyword text. This is real multi-component orchestration code, but task-specific automatic tool selection is not established by that fixed sequence. [Prediction path](https://github.com/Argho009/sih-2026/blob/d2217fe9417748fa9ca840ef07fe8610d9f34041/backend/services.py#L179), [question pipeline](https://github.com/Argho009/sih-2026/blob/d2217fe9417748fa9ca840ef07fe8610d9f34041/backend/services.py#L329), [API request models](https://github.com/Argho009/sih-2026/blob/d2217fe9417748fa9ca840ef07fe8610d9f34041/backend/app.py#L56).

Its separate GIS “agent” calls each available file-based tool in fixed order and sends results to an LLM synthesizer. The query does not choose tools in this function. It imports bi-temporal change but does not call it in the inspected analysis function. Header claims of LLM tool selection and zero numerical hallucinations exceed this code evidence. [GIS agent](https://github.com/Argho009/sih-2026/blob/d2217fe9417748fa9ca840ef07fe8610d9f34041/try/3_tool_agent_gis/agent.py#L76).

The upload endpoint validates extension/readability then converts TIFF/JPEG to RGB PNG; no CRS, timestamp, sensor-band or pair-compatibility contract is present in this endpoint. The inspected live API does not accept an optical–SAR or temporal pair. This is narrower than the toolbox's general multimodal language, not proof that no other experimental code exists. [Upload](https://github.com/Argho009/sih-2026/blob/d2217fe9417748fa9ca840ef07fe8610d9f34041/backend/app.py#L145), [toolbox README](https://github.com/Argho009/sih-2026/blob/d2217fe9417748fa9ca840ef07fe8610d9f34041/try/README.md).

Adaptation artifacts are more substantial than a model-name list: a Qwen2.5-VL LoRA config (rank 8, q_proj/v_proj), processor/tokenizer files and trainer history ending at global_step=1186, epoch=1 exist publicly. The history contains changing losses; it also includes NaN entries and no best evaluation metric. This supports “training artifacts exist,” not model correctness or benchmark accuracy. No adapter-weight blob was present in the inspected tree, and the serving code checks a different local adapter directory. The generated model-card README remains largely an unfilled template. [Adapter config](https://github.com/Argho009/sih-2026/blob/d2217fe9417748fa9ca840ef07fe8610d9f34041/colab/satquery_qwen_lora/final_adapter/adapter_config.json), [trainer state](https://github.com/Argho009/sih-2026/blob/d2217fe9417748fa9ca840ef07fe8610d9f34041/colab/satquery_qwen_lora/checkpoint-1186/trainer_state.json), [serving path check](https://github.com/Argho009/sih-2026/blob/d2217fe9417748fa9ca840ef07fe8610d9f34041/backend/services.py#L102), [model-card template](https://github.com/Argho009/sih-2026/blob/d2217fe9417748fa9ca840ef07fe8610d9f34041/colab/satquery_qwen_lora/final_adapter/README.md).

### Published accuracy is not measured by the supplied evaluator

The submission README/report claims 92.13% combined precision, 99.8% hallucination suppression, CNN Top-3 96.8%, RF 84.6%, VQA 91.4% and “verified” component status. The generator establishes a materially different story:

| Published quantity | What evaluation.py actually does |
|---|---|
| RF 84.6%, F1 0.812 | Returns constants; available images/models can contribute latency, without gold-label accuracy computation |
| CNN Top-1 89.2%, Top-3 96.8%, mAP 0.884 | Runs optional forward passes for latency, then returns constants; uninitialized model is possible if weights are absent/unloadable |
| GIS 100%, zero floating-point error | Calculates indices on three hard-coded vectors and returns fixed perfect scores without comparing a truth/reference |
| LLM JSON/intent/tool rates | Selects hard-coded rates by adapter-file existence |
| VQA 91.4%, IoU 0.742 | Checks LM Studio /models connectivity, then returns constants without VQA questions or gold boxes |
| Ensemble 92.13%, suppression 99.8% | Weighted arithmetic over the component constants; suppression and grounded integrity are fixed values |

Sources: [RF evaluator](https://github.com/Argho009/sih-2026/blob/d2217fe9417748fa9ca840ef07fe8610d9f34041/evaluation.py#L64), [CNN evaluator](https://github.com/Argho009/sih-2026/blob/d2217fe9417748fa9ca840ef07fe8610d9f34041/evaluation.py#L133), [GIS evaluator](https://github.com/Argho009/sih-2026/blob/d2217fe9417748fa9ca840ef07fe8610d9f34041/evaluation.py#L204), [LLM evaluator](https://github.com/Argho009/sih-2026/blob/d2217fe9417748fa9ca840ef07fe8610d9f34041/evaluation.py#L236), [VLM and ensemble evaluator](https://github.com/Argho009/sih-2026/blob/d2217fe9417748fa9ca840ef07fe8610d9f34041/evaluation.py#L275), [published report](https://github.com/Argho009/sih-2026/blob/d2217fe9417748fa9ca840ef07fe8610d9f34041/evaluation_report.md), [submission README](https://github.com/Argho009/sih-2026/blob/d2217fe9417748fa9ca840ef07fe8610d9f34041/send/README.md).

These are **not verified accuracy or hallucination rates**. This conclusion is about the supplied evaluator, not a claim that no separate private experiments occurred.

The two test-named files in the tree are model/training smoke scripts. The inspected LoRA script loads CUDA weights and performs one synthetic-image forward/backward/optimizer step; it is not an accuracy regression suite. The health helper also returns online=true and named models on its final fallback, so a green health response is not sufficient evidence of a functioning LM Studio model. ## Implications for our comparison and next decisions

The parent audit supplies our local comparison point as 7277935 (Nov 7), with 312 main tests, 86 Flood Lab tests, multiple specialists, actual terrain and real-case evidence. Those local facts were not independently re-audited in this note. The parent also distinguishes our public main fe8a038 (Oct 31) from this unpublished research checkout. Public competitors must be compared against the publicly inspectable snapshot when discussing public readiness; local unpublished capability can be reported separately with its evidence.

1. **Do not claim unique agent orchestration.** Divy and Cattolatte have implemented deterministic query/input routing and traceable specialists. Our differentiation must name a verified capability or evidence contract, not the word “agent.” Cattolatte's accepted ADR also shows why “no LLM planner” is not automatically a scope failure.
2. **Close publication and reproduction before adding models.** Publish a pinned source/result/checkpoint manifest and a minimal evidence-backed reproduction path for the local work. The inspected competitors' missing exact checkpoint identity is an opportunity only if we actually close ours.
3. **Test the product path against the evaluator path.** Cattolatte's fused-ranking mismatch is concrete evidence that a benchmark can measure an implemented capability the normal web request does not activate. Our regression should submit ordinary user inputs and inspect trace, selected model, effective parameters and output artifact.
4. **Treat calibrated confidence and difficult subsets as open work until measured.** Competitor confidence values are mainly softmax/embedding heuristics/constants. Our claim must report reliability/abstention or scoped score semantics, not borrow accuracy from a confidence label.
5. **Use a shared small benchmark before claiming stronger VQA/adaptation.** Cattolatte's broad VQA artifacts and Divy's task-specific temporal model justify taking them seriously. Our tests count and real-case arithmetic do not establish better VQA accuracy. Divy's generated temporal questions, Cattolatte's CDVQA subset and Argho's constants are not comparable denominators.
6. **Keep terrain/exposure claims scoped.** Divy has a terrain-classification head, so “competitors lack terrain” is too broad. Our actual terrain/hydrology and real-event evidence may differ in kind, but saved-input correctness, flood water fraction and infrastructure exposure accuracy are separate questions. Exposure accuracy remains unproven in the supplied local context.
7. **Stop model shopping until these evidence gaps are closed.** The highest-value next step is a public, pinned claim-to-evidence packet plus one serving-path parity check and one common held-out evaluation. More model names would increase scope before proving the control system.
